# NEXUS Arena 1.0 — режимы 1×1, 2×2, 5×5 и общий K/D

Полный исходный проект: веб-интерфейс (ПК/телефон), FastAPI + SQLite, роли, кланы, заявки, чат, турниры, 10 игр калибровки, проверка скриншотов модератором, K/D/A, спонсорская внешняя ссылка и Android WebView-клиент (Flutter).

## Что нового

- **Дуэль 1×1** — два одиночных игрока, свой ELO, свой ранг, своя калибровка 10 подтверждённых матчей.
- **Дуэт 2×2** — два игрока с каждой стороны. Можно начать поиск одному или вдвоём, не разделяя готовую группу. Рейтинг 2×2 не зависит от других режимов.
- **Команда 5×5** — прежний формат сохранён со старым ELO, рангом, победами и поражениями.
- **Отдельные рейтинговые таблицы** для всех трёх режимов.
- **K/D** — суммарные убийства / суммарные смерти во всех подтверждённых матчах независимо от режима. Если смертей 0, выводится «—» (отношение не определено). **Assists** остаются отдельной статистикой.
- Готовность теперь рассчитывается на **2 / 4 / 10** игроков. После игры капитаны обеих сторон прикрепляют скриншоты, администратор или разработчик подтверждает победителя; только потом +25/−25 ELO начисляется **именно в том режиме**, в котором был матч. Отказ или тайм-аут не меняют рейтинг.
- Названия рангов NEXUS («Искра» ... «Нексус») используются отдельно в каждой рейтинговой дисциплине, с собственными порогами ELO и подразделениями III–I.

## Запуск на компьютере Windows

1. Установите Python 3.10–3.14. Разархивируйте весь проект.
2. Если обновляете **существующий** NEXUS Arena 0.9, **сначала выключите** старый сервер и сделайте резервную копию `server/arena.sqlite3`. Скопируйте базу из старого проекта в `server/arena.sqlite3` в новой папке.
3. Запустите `START_NEXUS.bat`. При первом запуске установятся зависимости.
4. Откройте `http://127.0.0.1:8000` и нажмите **Ctrl+F5** для обновления стилей.
5. Выберите «Поиск матча» → «Создать лобби» → формат 1×1/2×2/5×5 → «Начать поиск».

Для получения **первой** роли владельца используйте `SETUP_OWNER_AND_START.bat`. Уже настроенная роль OWNER хранится в базе и **не сбрасывается** обновлением. Ни пароль, ни доступ разработчика в исходниках не зашиты.

## Android

Мобильный клиент использует *тот же веб-интерфейс и сервер*, включая новые режимы. Для установки на телефон нужен опубликованный сайт по HTTPS; `localhost` с другого телефона не открывается. В исходниках есть `BUILD_ANDROID_APK.bat` (Flutter + Android SDK) и `.github/workflows/build-android-apk.yml` (сборка GitHub Actions). **Готовый APK не включён** — в этой среде нет Flutter/Android SDK, и бинарник не был собран и протестирован на устройстве.

Дополнительно: `docs/UPDATE_AND_ANDROID_09_RU.md` и `docs/MODES_AND_KD_10_RU.md`.

## Проверки

- `python -m pytest -q tests/test_modes10.py` — независимые ELO, калибровка 10 игр, скриншоты, подтверждение, K/D, ограничение лобби.
- `node --check web/app.js` и `node tests/check_ui_templates10.js` — синтаксис и формирование основных HTML-экранов.
- `python -m pytest -q tests/test_server.py` — регрессионная проверка 5×5 и существующего API.
- **Запускайте Python-тесты по одному файлу**, потому что старые тестовые модули задают отдельные временные базы при импорте.

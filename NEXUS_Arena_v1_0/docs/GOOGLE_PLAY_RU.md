# Как подготовить NEXUS Arena 0.6 к Google Play (ориентир: октябрь 2026)

**Важно:** владелец аккаунта Google Play Console должен быть не младше 18 лет. Для регистрации взимается однократный платёж **US$25**. Если разработчик моложе 18, публикацию может законно вести совершеннолетний оператор/организация, принимающий ответственность за приложение; не указывайте недостоверные данные и не пытайтесь обходить возрастные требования.

## 1. Что уже подготовлено

- `web/` — адаптивная веб-версия и PWA, работает с сервером.
- `server/` — API, база пользователей, кланы, чат, турниры, администрирование.
- `mobile/` — проект Android на Flutter WebView, отображающий **этот же опубликованный HTTPS-сайт**.
- `web/icons/icon-512.png` — иконка 512×512 для Play; `docs/feature-graphic-1024x500.png` — промографика; `docs/desktop_home.png` и `docs/mobile_clan_chat.png` — примеры интерфейса (для магазина нужны чистые реальные скриншоты с устройства).
- `web/account-deletion.html` и `/account-deletion` — веб-страница удаления аккаунта, также есть удаление в настройках.

## 2. Сделать сайт доступным

Развернуть на публичном HTTPS-домене (см. `DEPLOY_RU.md`), настроить админ-аккаунт и проверить регистрацию двух реальных телефонов, чат, удаление аккаунта, модерацию. URL без сервера в APK не заработает.

## 3. Собрать приложение для Android

Установить Flutter, Android Studio, Android SDK и Android API 36. На Windows можно запустить **`BUILD_ANDROID_APK.bat`** из корня проекта: указать доступный в интернете HTTPS-адрес сервера и получить тестовый APK. Для публикации Google Play нужен App Bundle. Выполнить в папке `mobile`:

```bash
flutter create --platforms=android --org com.yourbrand .
flutter pub get
cd ..
python tools/install_android_icons.py
cd mobile
flutter doctor
flutter build appbundle --release --dart-define=ARENA_URL=https://ВАШ-ДОМЕН
```

В Android Gradle-конфигурации проверить `compileSdk` и `targetSdk` **не ниже API 36**, требуемого для новых релизов начиная с 31 августа 2026 г. Настроить безопасное **release-подписание**, уникальный `applicationId`, `versionCode` и хранение секретного ключа вне исходников. В результате должен появиться `.aab` примерно в `build/app/outputs/bundle/release/`.

**Это WebView-клиент: до публикации рекомендуется добавить функции, повышающие ценность именно мобильного приложения (например, уведомления о принятии заявки или о найденном матче). Google Play проверяет качество и соответствие требованиям — публикация не гарантирована.**

## 4. Заполнить Play Console

Совершеннолетний владелец Play Console регистрирует аккаунт на https://play.google.com/console, создаёт приложение, указывает название, категорию, контакты, описание, иконку 512×512, feature graphic 1024×500, скриншоты. Заполняет разделы App content: целевая аудитория, Content rating, Data safety, политика конфиденциальности, доступ к приложению для ревьюера (тестовый аккаунт), реклама (если её нет, так и указывает). Ссылка для удаления: `https://ВАШ-ДОМЕН/account-deletion`.

Для **новых личных** аккаунтов Play Console, созданных после 13 ноября 2023 года, перед Production требуется закрытое тестирование минимум **12 пользователей, непрерывно подключённых 14 дней**, затем заявка на доступ к продакшену. Проверьте текущие требования по официальной документации.

## 5. Что обязательно доделать до подачи

1. Заменить шаблоны `web/privacy.html` и `web/terms.html` на актуальные документы с реальным оператором, службой поддержки и сроками хранения данных.
2. Протестировать корректную работу ссылок на условия и политику в WebView (внешние открытия в мобильной оболочке пока заблокированы для безопасности).
3. Обеспечить постоянную модерацию клановых сообщений, ответ на жалобы, ограничения на спам, защиту персональных данных и бэкапы.
4. Внедрить восстановление пароля и подтверждение email; добавить способы связи с поддержкой.
5. Определиться с позиционированием приложения для возрастной аудитории; не вводить взносы/ставки и не обещать выплаты, которые не подтверждены.
6. Проверить лицензирование названия/изображений/материалов игры и обозначить NEXUS как **неофициальную** площадку.
7. Запустить closed test, исправить ошибки, предоставить валидный тестовый аккаунт ревьюеру и затем подать релиз.

## Дополнения NEXUS 0.6

Управление временем турнира и регистрацией выполняется на сервере и доступно на Android через тот же HTTPS-сайт; калибровка ранга также общая. Не пытайтесь отправлять APK в Play Console вместо AAB. Файл `BUILD_ANDROID_APK.bat` для локального тестового APK **требует установленного Flutter и Android SDK**. Существующие аккаунты и чаты требуют базы данных серверного проекта; APK не содержит базу пользователей.

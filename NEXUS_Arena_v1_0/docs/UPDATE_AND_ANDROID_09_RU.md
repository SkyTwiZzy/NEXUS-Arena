# NEXUS Arena 0.9: обновление, роли, спонсирование, Android

## Обновление сайта с сохранением пользователей
1. Остановите прежний NEXUS Arena и сохраните отдельную копию `server/arena.sqlite3`.
2. Распакуйте новую версию **в другую папку**. Перенесите файл `server/arena.sqlite3` при выключенном сервере.
3. Для первоначального владельца запустите **`SETUP_OWNER_AND_START.bat`** (либо `START_NEXUS_DEVELOPER.bat`). Откроется консоль, в которой нужно указать **свой адрес электронной почты** и пароль в скрытом поле. Если учётная запись уже существует, введите **её текущий пароль**. Повторно регистрировать email через сайт не нужно. Если пароль не подходит, программа не выдаст права владельца. Никакие роли нельзя получить по надписи DEVELOPER в интерфейсе.
4. При следующих запусках достаточно `START_NEXUS.bat`. Перейдите на `http://127.0.0.1:8000` и нажмите `Ctrl+F5`. Если настроена публичная база на сервере, первичную роль владельца создаёт оператор через `ADMIN_EMAIL` и `ADMIN_PASSWORD` в переменных окружения сервера (не в HTML и не в репозитории).
5. **Никогда не публикуйте в интернете исходный пароль, секретный .env, SQLite с настоящими аккаунтами или консольный лог, содержащий секреты.** Если пароль уже раскрыт в переписке, задайте новый при настройке владельца. Если профиль с прежним паролем уже создан, сначала смените пароль безопасным способом на сервере.

## Роли и права
- **Владелец:** имеет роль `OWNER`, единственный; полный доступ, назначает `DEVELOPER`, `ADMIN`, `MODERATOR`, может указать/убрать внешнюю ссылку спонсирования.
- **Разработчик:** роль `DEVELOPER`, доступ к панели и управлению контентом, назначает `ADMIN` и `MODERATOR`. Не может менять владельца или других разработчиков.
- **Администратор:** роль `ADMIN`, панель управления и проверка матчей, но не выдача ролей.
- **Модератор:** роль `MODERATOR`, проверка скриншотов матчей, ввод K/D/A и отмена незавершённого матча; без главной административной панели.
- **Игрок:** роль `PLAYER`.

Роли видны на странице «Профиль» и доступны в `GET /api/me`. Назначение прав осуществляется только через сервер и записывается в `role_audit`. При смене роли активные сессии изменённого пользователя инвалидируются: ему нужно войти заново. Предыдущие роли `is_admin` / `is_moderator` мигрируют автоматически.

## Спонсирование
В «Развитие проекта» показываются цель финансирования и добровольная поддержка. По умолчанию кнопка недоступна. Владелец должен выбрать проверенный сервис, самостоятельно выполнить его требования и указать полный HTTPS-адрес страницы оплаты в панели разработчика. Пользователь видит, что переходит на отдельный сайт. Приложение **не получает и не сохраняет платёжные реквизиты, не отслеживает перечисления и не обещает вознаграждений**. Чтобы отключить, очистите поле URL. Использование внешних платежей в приложении, опубликованном в Google Play, нужно отдельно проверить на соответствие политикам Google Play.

## Android: сделать APK на компьютере
Android-приложение — WebView-клиент общей платформы. Для полноценной работы на телефоне сайт и API **должны быть развернуты на общедоступном HTTPS-адресе**, а не только на `127.0.0.1` ПК. 

**Способ 1, Windows:** установите Flutter, Android Studio и Android SDK. Из корня проекта запустите `BUILD_ANDROID_APK.bat`, укажите адрес сайта. После сборки файл `NEXUS_Arena_v0_9.apk` появится в корне. Это APK для тестовой установки, а не готовый релиз в Google Play.

**Способ 2, облачная сборка GitHub Actions:** создайте частный GitHub-репозиторий, загрузите проект (не загружайте `.env`, `server/arena.sqlite3`, пароли и другие персональные данные). В Settings → Secrets and variables → Actions → Variables добавьте `NEXUS_SITE_URL` со значением `https://ваш-домен`. Откройте Actions → **NEXUS Arena Android APK** → **Run workflow**. После удачной сборки скачайте ZIP из Artifacts и распакуйте `app-release.apk`. Доступность GitHub Actions и правила использования зависят от GitHub-аккаунта.

**Готовый APK не находится в исходниках:** Flutter SDK и Android SDK не установлены в среде подготовки. Облачную сборку фактически нужно выполнить на GitHub.

## Что ещё необходимо перед публичным релизом
Развёртывание HTTPS с резервными копиями, подтверждение email и восстановление пароля, защита от спама и модерация, политика конфиденциальности и юридическая проверка спонсирования, релизное подписание AAB и тестирование на физических устройствах. Это всё ещё предварительная версия проекта, не публикация в Google Play.

**Смена пароля:** «Профиль» → «Сменить пароль». Потребуется текущий пароль, после смены нужно войти заново. Если пароль был раскрыт в переписке, рекомендуется поменять его до публикации сайта.

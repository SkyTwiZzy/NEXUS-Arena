# NEXUS Arena 1.1 — как открыть сайт всему интернету

Сайт **не становится общедоступным** только после распаковки архива. Нужно либо запустить публичный HTTPS-туннель из своего Windows-компьютера (временная ссылка), либо разместить сервер у хостинг-провайдера (постоянная ссылка). **Выбирайте второй вариант для настоящего запуска.**

## Вариант А: быстро показать друзьям, без домена (Windows)

Это **временный доступ для тестирования**, а не постоянный хостинг.

### Шаг 0: подготовьте аккаунт владельца

1. Распакуйте архив целиком, например в `C:\NEXUS_Arena` (не запускайте из ZIP).
2. При обновлении старой версии: **остановите прежний сервер**, скопируйте старый `server/arena.sqlite3` в новую папку по такому же пути. Сохраните копию базы отдельно. Не публикуйте этот файл.
3. Если владелец ещё не настроен, запустите `SETUP_OWNER_AND_START.bat`, введите свои данные, дождитесь открытия сайта. После настройки закройте сервер. Если владелец есть, этот шаг пропустите.
4. **Смените пароль владельца, если ранее публиковали его в чате.** Профиль → шестерёнка → смена пароля. Это следует сделать **до** открытого доступа.

### Шаг 1: установите Cloudflare Tunnel

Установите **cloudflared** по официальной инструкции:
https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/

Для Windows можно запустить PowerShell и выполнить:

```powershell
winget install --id Cloudflare.cloudflared -e
```

Если `winget` отсутствует, загрузите официальный `cloudflared.exe` с сайта Cloudflare и положите его прямо в папку проекта возле `.bat`-файлов. Перезапустите командную строку после установки.

### Шаг 2: включите общий доступ

1. Дважды нажмите **`START_NEXUS_PUBLIC_SERVER.bat`** и оставьте окно открытым. Установка Python-библиотек может занять несколько минут.
2. Откройте **второе** окно двойным щелчком на **`START_PUBLIC_LINK.bat`**.
3. В новом окне будет выведена ссылка `https://...trycloudflare.com`. **Это настоящий публичный HTTPS-адрес, пока оба окна открыты.**
4. Отправьте ссылку другу или откройте на телефоне **через мобильный интернет** (Wi-Fi можно отключить для проверки).

**Ограничения:** компьютер должен быть включён, оба окна должны работать, после нового запуска будет другая ссылка. Cloudflare Quick Tunnel предназначен для тестирования, без гарантии доступности и без постоянного адреса. Не создавайте большой публичный запуск на нём.

**Если ошибка:** проверьте `http://127.0.0.1:8000/api/status` локально. Если сервер работает, но внешней ссылки нет, проверьте интернет и установленный `cloudflared.exe`. Никогда не пересылайте пароли или содержимое `.env`.

### Почему не запускать обычный START_NEXUS.bat?

Он включает режим для локального HTTP (`COOKIE_SECURE=0`). Новый публичный файл запускает сервер для HTTPS-туннеля (`COOKIE_SECURE=1`), а значит браузер передаёт сессионные cookies только через защищённое соединение. Не открывайте его напрямую по незащищённому HTTP для входа.

## Вариант Б: постоянный публичный адрес Render

> Для базы SQLite **нужен оплачиваемый сервис с подключённым постоянным диском**. На эфемерном бесплатном хостинге регистрации и матчи могут исчезать после перезапуска/деплоя. Цены и условия сверяйте на сайте Render.

1. Создайте приватный репозиторий GitHub. Загрузите **файлы из корня** этого проекта, включая `Dockerfile`, `render.yaml`, папки `server` и `web`. **Никогда не загружайте** `.env`, `arena.sqlite3`, пароли, фотографии и файлы резервных копий. При необходимости используйте GitHub Desktop.
2. Откройте https://dashboard.render.com/ и выберите создание **Blueprint** из GitHub-репозитория. Конфигурация находится в `render.yaml`.
3. При настройке переменных `ADMIN_EMAIL` и `ADMIN_PASSWORD` введите **свои** данные владельца и новый сильный пароль (не публикуйте его). Убедитесь, что сервис **платный Starter или выше** и диск `/data` создан.
4. После запуска откройте адрес HTTPS, выданный Render (`https://...onrender.com`). Не копируйте пример адреса — нужен **фактический** адрес из панели Render.
5. Проверьте `https://ВАШ-АДРЕС/api/status` и вход владельца.
6. После успешного создания OWNER удалите `ADMIN_PASSWORD` и `ADMIN_EMAIL` из переменных сервиса в панели Render и повторно выполните Deploy, **не удаляя диск**; старый аккаунт OWNER останется в базе.
7. Желательно установить переменную `PUBLIC_ORIGIN` равной точно этому HTTPS-адресу (без завершающего `/`). Это фиксирует разрешённый источник запросов. `COOKIE_SECURE=1` обязателен.
8. Для Android укажите этот же адрес при сборке через `--dart-define=ARENA_URL=https://...` или переменную `NEXUS_SITE_URL` в GitHub Actions.

**Важно для сохранения прежних аккаунтов:** при новом размещении база **изначально пустая**. Чтобы перенести старые аккаунты и кланы, сначала остановите сервис, безопасно скопируйте старую `arena.sqlite3` на постоянный диск `/data/arena.sqlite3`, после чего запускайте его. У Render нет универсальной кнопки переноса локального SQLite через Blueprint. Если перенос не нужен, начните с новой базы.

**Про возможности и ограничения Render:** https://render.com/docs/disks

## Вариант В: свой VPS и домен

1. Потребуется VPS с Docker Engine + Docker Compose и домен. Настройте DNS A-запись на публичный IPv4 сервера; убедитесь, что открыты порты 80 и 443.
2. На VPS скопируйте исходники, затем скопируйте `.env.public.example` в `.env` и замените *все* примерные значения; задайте новый уникальный пароль администратора. Не публикуйте `.env` в репозитории.
3. Запустите из корневой папки `docker compose up -d --build`.
4. Caddy (в `Caddyfile`) автоматически настроит HTTPS, если DNS работает, домен доступен снаружи и порты открыты. Откройте `https://ВАШ-ДОМЕН`.
5. Проверьте сервер: `docker compose logs --tail=100 app caddy`, и API: `https://ВАШ-ДОМЕН/api/status`.
6. Сделайте резервную копию SQLite из каталога `./data/`. Не используйте один и тот же SQLite-файл для нескольких процессов. Для высокой нагрузки понадобится PostgreSQL и другая серверная архитектура.

**Действующая конфигурация** сохраняет базу в `./data/arena.sqlite3` на VPS, а Render — на `/data/arena.sqlite3` внутри постоянного диска.

## Перед открытым запуском

- Смените старый пароль разработчика; ограничьте права администратора только проверенным сотрудникам.
- Прочитайте и заполните `web/privacy.html` и `web/terms.html` настоящими данными оператора и контактами. Реализуйте подтверждение email / восстановление доступа, постоянную модерацию и резервное копирование перед привлечением большого числа пользователей.
- Не загружайте `.env`, дампы базы и чужие скриншоты матчей в открытый доступ.
- Режимы, кланы, чат, отчёты и турниры работают внутри NEXUS Arena. **NEXUS не подключён к официальному API MLBB** и не создаёт игровые комнаты автоматически.
- Запускать монетизацию и денежные выплаты без оформления, проверки требований платёжной платформы и правил игры нельзя. Спонсорская ссылка — лишь внешний переход.

## Резервная копия на Windows

`BACKUP_ACCOUNTS.bat` делает корректную SQLite-копию даже если сервер запущен. Копия появится в `backups/arena_ДАТА.sqlite3`. Папку `backups` нельзя выкладывать на сайт или в GitHub.
